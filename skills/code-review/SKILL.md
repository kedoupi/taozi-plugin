# Taozi Code Review

## 何时使用

- 用户要求 review、审查、检查代码、找风险
- 准备合并、发布或做质量回归
- 需要明确列出 bug、回归点、安全问题和测试缺口

## 工作方式

1. 先确认审查范围
2. 优先找行为风险，不先做风格评论
3. 结合变更上下文验证是否会引入回归
4. 明确指出缺失测试和未验证区域

## 输出要求

- 先给 findings，按严重程度排序
- 每条 findings 尽量带文件路径和原因
- 如果没有明显问题，要明确说明“未发现实质性问题”
- 最后补充剩余风险和验证缺口

## 审查清单

- 逻辑是否正确，是否改变原有语义
- 错误处理、边界条件、空值路径是否完整
- 安全基线是否被削弱
- 并发、状态同步、缓存、事务是否可能失效
- 测试是否覆盖主要正反路径
