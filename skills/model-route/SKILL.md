# Model Route

分析任务 `$ARGUMENTS`，推荐最合适的 Claude 模型，避免用 Opus 做简单任务浪费成本。

## 何时使用

- 需要为具体任务选择模型
- 构建多代理流水线要拆分模型职责
- 成本敏感、需要降级策略

## 决策原则

- **默认 Sonnet**：不确定时选 Sonnet
- **Opus 有门槛**：必须有明确的"深度推理"需求才用 Opus
- **Haiku 专用**：只用于明确的简单/重复任务
- **混合策略**：复杂流水线中不同步骤用不同模型
- 高风险任务优先保守，不只看速度
- 一个任务能拆阶段时，优先分阶段路由

## 路由矩阵

### Opus（最强推理，高成本）

**适用**：
- 复杂架构设计、技术选型决策
- 多步推理、需要深度理解的 debug
- 提示词优化、AI 系统设计
- 高风险代码（支付、安全、数据迁移）
- 创造性解决方案

**不适用**：重复性任务、文档更新、简单 CRUD

### Sonnet（平衡，默认）

**适用**：
- 大多数功能开发
- 代码审查
- 测试编写
- 文档生成
- 重构和清理

**特点**：性价比最高，80% 场景的正确选择

### Haiku（快速，低成本）

**适用**：
- 简单格式转换
- 变量命名建议
- 代码片段补全
- 语法检查
- 简单问答

## 任务评估

```markdown
### 任务评估

**复杂度**: [低/中/高]
- 推理步骤数量: [1-3 / 4-8 / 9+]
- 是否需要架构思考: [是/否]
- 是否涉及安全/金融: [是/否]

**速度要求**: [实时响应 / 正常 / 可等待]
**Token 预算**: [紧张 / 正常 / 充足]

### 推荐模型: [Opus / Sonnet / Haiku]
**理由**: [1-2 句话说明]
**替代方案**: 如果 [条件]，可降级到 [模型]

### Agent 配置建议
- 规划/决策 Agent: Opus
- 执行 Agent: Sonnet
- 格式化/总结 Agent: Haiku
```
