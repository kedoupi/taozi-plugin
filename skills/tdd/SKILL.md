# Taozi TDD

## 核心循环

1. RED: 先写一个会失败的测试
2. GREEN: 只写足够让测试通过的最小实现
3. REFACTOR: 在测试保护下整理代码

## 约束

- 不要先写完整实现再补测试
- 每轮只解决一个清晰行为
- 如果测试难写，先缩小需求或重构入口

## 实施步骤

1. 提炼出一个可验证行为
2. 写失败测试并确认失败原因正确
3. 写最小实现直到测试通过
4. 清理重复、命名和结构
5. 继续下一轮

## 输出要求

- 说明当前处于 RED、GREEN 还是 REFACTOR
- 标记新增或修改的测试
- 说明尚未覆盖的边界
