# Update Context

分析目录 `$ARGUMENTS`（默认 cwd），创建或增量更新长期上下文文档。

## 何时使用

- 新接手模块，需要快速建立目录说明
- 代码结构变化较大，需要更新职责说明
- 用户明确要求"更新上下文"或"补 codemap"

## 文档位置

- Claude 侧优先使用 `CLAUDE.md`
- Codex 侧优先使用 `AGENTS.md`
- 仓库已明确采用某一种时，遵循现有模式

## 禁忌

- 不粘贴大段代码
- 不生成会频繁过时的细节
- 不把临时调试过程写进长期上下文
- 不覆盖用户手写内容（增量更新）

## 执行步骤

### 1. 扫描目录结构

- 列出主要文件和子目录
- 识别代码文件、配置文件、测试文件

### 2. 分析模块职责

- 根据文件名和内容推断模块用途
- 识别导出的主要功能
- 识别依赖、测试入口、风险点

### 3. 更新策略

- 如果 CLAUDE.md 不存在 → 创建新文件
- 如果已存在 → 读取现有内容，增量补充，保留用户手写内容

### 4. 推荐结构

```markdown
# [模块名称]

## 职责
- 模块的核心功能

## 关键文件
- `file.ts` — 描述

## 依赖关系
- 依赖: xxx
- 被依赖: xxx

## 注意事项
- 开发时需要注意的点

## 变更记录
- YYYY-MM-DD: 变更摘要
```

### 5. 变更记录规则

- 格式: `- YYYY-MM-DD: 简短摘要`
- 追加到 `## 变更记录` 末尾
- 同一天的多次更新合并为一条

## 重要原则

- 保持简洁，不贴代码片段
- 增量补充，不覆盖用户手写内容
- 完成后简要说明更新了什么
