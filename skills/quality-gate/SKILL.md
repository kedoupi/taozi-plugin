# Taozi Quality Gate

## 目标

在交付或发布前，判断当前改动是否达到放行标准。

## 检查顺序

1. 构建或类型检查
2. 单元测试和集成测试
3. lint 或静态检查
4. 安全与配置风险
5. 文档和回滚信息是否齐全

## 放行原则

- 任一关键检查失败，不应放行
- 缺少验证证据时，结论应为“未通过”或“有条件通过”
- 不能用主观判断替代测试或构建结果

## 输出要求

- 明确给出 `PASS`、`CONDITIONAL PASS` 或 `FAIL`
- 每个检查项标注状态和证据
- 给出最短修复路径
