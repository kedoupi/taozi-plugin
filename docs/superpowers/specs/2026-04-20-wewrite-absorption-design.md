# wewrite 能力吸收到 wechat skill 设计文档

**日期**：2026-04-20
**目标**：把 [wewrite](https://github.com/oaker-io/wewrite) 在「写作骨架 / 内容增强 / 多平台热搜」三个方向的能力，以参考资料 + Sub-Agent prompt 改造的方式吸收进 `skills/wechat/`，不引入新依赖、不破坏现有三 Agent 流水线。

---

## 1. 现状盘点

| 能力 | wewrite 有 | taozi/wechat 现状 |
|------|-----------|------------------|
| 写作骨架（多框架） | ✅ 7 类框架 | ❌ 完全缺失 |
| 写中主动增强 | ✅ 角度/密度/锚定/体感 | ⚠️ 仅 L1–L4 写后质检（被动） |
| 多平台热搜 | ✅ 多源聚合 + 评分 | ⚠️ 单次 YouMind webSearch；history.yaml 文件存在但 Sub-Agent A 未读取 |

## 2. 整体架构

```
Sub-Agent A (选题/热搜)
  ├─ [新] Read history.yaml → 提取近 30 天选题关键词
  ├─ [新] YouMind 调研 ×3 路并行（行业热点 / 破圈话题 / 竞品对标）
  ├─ [新] 候选池合并去重 + history dedup
  ├─ [新] 3 维打分（热度 0.4 / 相关性 0.4 / SEO 0.2）→ top10
  └─ 输出: 1 推荐 + 3 备选 + 评分理由

Sub-Agent B (写作)
  ├─ [新] Read frameworks.md → 框架选择（7 选 1） → 报告
  ├─ [新] Read enhancements.md → 按框架查"必启用 + 推荐启用"
  ├─ [新] 框架段落骨架 + 增强指令注入写作 prompt
  ├─ 写作（沿用现有逻辑）
  ├─ L1–L4 写后质检（已存在，作为兜底）
  └─ 输出: 草稿 + 元信息（框架名 + 启用增强项）

Sub-Agent C (配图+发布) — 不变
```

**新增 / 改动文件**：

## 3. 方向 1：写作骨架

### 3.1 7 框架定义（frameworks.md 内容结构）

每个框架文档包含 4 节：**适用场景 / 段落骨架 / 一句话范例 / 反例避坑**。

| # | 框架 | 适用 | 段落骨架 |
|---|------|------|---------|
| 1 | 痛点型 | 工具/方法/教程类 | 场景痛点 → 旧方案为什么不行 → 新方案登场 → 3 个用法 → 效果对比 → 行动召唤 |
| 2 | 故事型 | 人物/案例/经历 | 反常识开头 → 背景铺垫 → 转折冲突 → 关键决策 → 结果 → 抽象出方法论 |
| 3 | 清单型 | 资源/工具盘点 | 痛点引入 → N 项总览 → 逐项展开 → 怎么挑 → 收藏行动 |
| 4 | 对比型 | 选型/测评 | 共同问题 → 维度定义 → A 怎么做 → B 怎么做 → 维度评分 → 推荐场景 |
| 5 | 热点解读型 | 时事/新闻 | 事件复述 → 主流解读 → 我的角度 → 3 个被忽略的事实 → 趋势预判 |
| 6 | 纯观点型 | 行业洞察/趋势 | 反直觉论点 → 论据 1/2/3 → 反方质疑 → 我的回应 → 落地建议 |
| 7 | 复盘型 | 项目/事件回顾 | 起点（目标/约束） → 关键节点 → 哪里赌对 → 哪里翻车 → 数据 → 下次会怎么做 |

### 3.2 框架选择逻辑（注入 Sub-Agent B prompt 顶部）

```
判断顺序（自上而下，第一个命中为准）:
  1. 素材含完整项目周期 → 复盘型
  2. 素材含 5+ 项资源 → 清单型
  3. 素材含评测/对比 → 对比型
  4. 素材含人物/经历 → 故事型
  5. 选题与时事/新闻强关联 → 热点解读型
  6. 用户素材为纯思考/无具体数据 → 纯观点型
  7. 默认（教程/工具/方法类） → 痛点型

输出: B Agent 报告"选定框架: {名} | 理由: {一句话}"
不阻塞用户确认，但元信息记录便于回顾
```

### 3.3 与 Sub-Agent B 衔接

- B 的 prompt 第一步从「直接写」改为「Read frameworks.md → 选择 → 报告 → 注入骨架到 system prompt → 写」
- 草稿末尾追加元信息行：`<!-- 框架: 痛点型 | 增强: 密度强化+细节锚定 -->`

## 4. 方向 2：内容增强

### 4.1 4 类增强策略（enhancements.md 内容结构）

| 策略 | 做什么 | 触发示例 |
|------|--------|---------|
| 角度发现 | 找到主流之外的第二/第三角度，给出 1+ 反共识切入 | "X 好"→"X 在 Y 场景反而差" |
| 密度强化 | 每 200 字至少 1 个具体数字/案例/引述 | "提升效率"→"3h 压到 22 分钟" |
| 细节锚定 | 用具体名字/时间/产品代替泛指 | "某公司"→"字节 2024 Q3 OKR" |
| 真实体感 | 感官词、第一人称、对话还原现场 | "用着不错"→"打开愣了 3 秒" |

### 4.2 类型 → 增强映射表

| 框架 | 必启用 | 推荐启用 |
|------|--------|---------|
| 痛点型 | 密度强化 + 细节锚定 | 真实体感 |
| 故事型 | 真实体感 + 细节锚定 | — |
| 清单型 | 密度强化 | 细节锚定 |
| 对比型 | 密度强化 + 真实体感 | — |
| 热点解读型 | **角度发现** | 密度强化 |
| 纯观点型 | **角度发现** + 密度强化 | — |
| 复盘型 | 真实体感 + 密度强化 | 细节锚定 |

### 4.3 与 Sub-Agent B 衔接

- B 选完框架后查映射表，把"必启用 + 推荐启用"展开成 prompt 指令注入写作 system prompt
- **写中主动约束**，非写后修补
- L1–L4 质检继续作为兜底，不替换

## 5. 方向 3：多平台热搜（YouMind 调研驱动）

### 5.1 子任务 3a：history.yaml 接入去重

**改动**：
- Sub-Agent A 第一步 Read `skills/wechat/history.yaml`
- 提取近 30 天选题关键词集合
- 候选评分阶段：与历史相似度 >70% 直接淘汰
- 写完文章后追加新条目（写入逻辑已存在，确认连通即可）

### 5.2 子任务 3b：YouMind 三路调研 + 打分

**3 路并行 query**：

| 路 | Query 模板 | 模拟效果 |
|----|-----------|---------|
| 行业热点 | `{用户行业} 本周热点 / trending / 讨论度高` | 微博/知乎热榜 |
| 破圈话题 | `{用户行业} 出圈 / 跨界 / 普通人也在聊` | 抖音/小红书爆款 |
| 竞品对标 | `{用户领域} 头部公众号 近期高赞文章主题` | 同行选题 |

**3 维打分**（每候选 0–10，加权汇总）：

| 维度 | 权重 | 评估方式 |
|------|------|---------|
| 热度 | 0.4 | 出现路数（1 路=3，2 路=6，3 路=10） |
| 相关性 | 0.4 | 与公众号定位语义相关度（B Agent 判断） |
| SEO | 0.2 | 标题含搜索高频词（YouMind 调研附带提示） |

**输出**：top 10 候选 → 推荐 1 + 备选 3，附【热度/相关性/SEO】打分 + 一句推荐理由

### 5.3 与 Sub-Agent A 衔接

- A 的 prompt 由「单次 webSearch」改为「3 路并行调研 → 合并去重 → history dedup → 打分 → 报告 1+3」
- YouMind 接口不变，只是用 3 套不同 query 调用 3 次

## 6. 错误处理

| 异常 | 行为 |
|------|------|
| frameworks.md / enhancements.md 缺失 | Sub-Agent B 警告，回退原写作流程，不阻塞 |
| YouMind 3 路某路失败 | 用剩余路结果，标注"仅 2 路数据" |
| 3 路全失败 | A 报错并提示用户检查 YouMind 配置 |
| history.yaml 损坏 | 跳过 dedup，stderr 记录，不阻塞 |
| 候选池为空（全被淘汰） | 提示用户放宽时间窗口或换关键词 |
